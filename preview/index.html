    The early route lesson

    Keep the path compatible with the host

    Early Flex Consumption testing led the team to use simple, single-segment route names. The June 29 runbook warns against introducing nested or hyphenated routes without testing them on the intended host.

    Evidence limit: the old notes preserve the decision, not the original failure trace. They do not establish that Azure Functions cannot support nested paths.

    A missing route became a parsing error

    1. Frontend expected a routeThe employee/client controls called endpoints absent from the deployed backend.
    2. Server returned empty 404The browser had no JSON result to read.
    3. Old code parsed it anywayThe visible JSON error distracted from the missing endpoint.

    Different failures need different checks

    API 404: inspect the exact host, method, registered route, shields and package.

    Page deep-link 404: inspect website fallback and asset delivery.

    401 / 403: inspect identity, role and record access.

    Zero functions: inspect entrypoints and load errors; keep compiled tests out of production discovery.
